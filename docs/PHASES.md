# 持续开发总指令 — Phase 01–12 路线图

> 依据 2026-11-26《FoldFly 全项目持续开发总指令》制定。总指令只给定目标清单与「Phase 01 至 Phase 12 顺序推进」的执行方式,未定义各阶段内容;本文件是本轮开发对 12 个阶段的具体化,是阶段验收与交付记录的基准。
> 硬性原则(AGENTS.md)全部继续有效:引擎与渲染彻底分离、气动参数由几何+纸张推导(禁止按机型硬编码)、三个校准锚点数量级吻合、机型是数据文件、引擎逻辑必须有单测。

## 二、与现行规范的冲突与范围修订(不隐瞒)

1. **BRIEF.md 非目标「自由画折痕的任意折叠隔离在远期」**:总指令明确把"自由折纸设计"列入本轮交付。修订:Phase 03 只做**受限自由折**——用户画折痕 + 现有层原语(整叠/顶层/塞入)+ 严格几何校验,不可折叠的输入(层序矛盾、非半平面折)被明确拒绝,不做层序求解近似。任意层序问题仍不解决。
2. **硬性约束「渲染 v1 用 Canvas 2D」与 PLAN.md M4「Three.js」**:Canvas 2D 仍是默认渲染与无障碍回退;Phase 05 新增 Three.js 作为**可选** WebGL 视图。三维渲染器只消费物理/几何结果,不反哺任何物理量。
3. **BRIEF.md 非目标「物理级 FEM 纸张仿真」**:Phase 01 的材料模型是**参数化材料库**(厚度/抗弯刚度等经验公式,来源与近似性质逐项标注),不是 FEM,不违反该非目标。
4. **BRIEF.md 非目标「多人对战与排行榜后端」**:Phase 07/08/09 的比赛、生涯、成就全部为本地 localStorage,无后端、无联网。
5. **版本纪律**(总指令第六节):凡改变共享轨迹的物理改动(Phase 02、Phase 04)必须递增 `FLIGHT_MODEL_VERSION`,重跑 `npm run calibrate` 全锚点回归;ghost/分享键已内嵌版本号,旧数据自然归档不混合排名。校准锚点在**完美折痕/默认材质**下保持数量级吻合,折痕质量与材质只在退化方向起作用,不得借"材质"名义重新拟合锚点。

## 三、阶段定义

### Phase 01 — 纸张材料模型(纯逻辑库)
- **内容**:`src/paper/material.ts`:由材质等级 × 克重推导厚度(标定系数)、体积密度、MD/CD 抗弯刚度(杨氏模量 × t³/12)、各向异性比、最小折叠半径、折痕利落度;全部为经验公式并标注来源区间。新增纸张**材质等级**维度(复印纸/激光纸/铜版纸/折纸专用纸/新闻纸,默认复印纸=现状行为)。UI 材质选择器与材料参数展示;校准/气动报告打印材料列;分享链接增加可选 `grade` 字段(缺省=兼容旧链接)。
- **红线**:不改飞行物理(不递增 FLIGHT_MODEL_VERSION);质量仍只由面积 × gsm 决定,厚度不影响质量(gsm 本身即面密度)。
- **验收**:material 单测(公式单调性、文献区间、退化输入);全量测试绿;校准输出与基线一致;旧分享链接兼容。

### Phase 02 — 折痕精度与材料→气动耦合(FLIGHT_MODEL_VERSION 4)
- **内容**:手动折叠记录每步折痕偏差(拖动落点与目标/折痕线的偏差),聚合为折痕质量 ∈ [0,1];自动演示/跳过教学=完美质量。耦合通道(全部为标注过的经验代理,退化方向正确):折痕质量 → 有效 Oswald e 折减与 CD0 增加;材质刚度 → 翼面定形保持(软纸高速洗出、硬纸折痕回弹)。完美折痕 + 默认材质下与 v3 轨迹逐位一致(锚点零漂移)。
- **验收**:v4(质量=1)与 v3 结果一致的等价性测试;质量递减的成绩单调性测试;校准全锚点回归;旧 ghost/分享自动归档不混合(版本键);折痕质量参与结算 UI 展示。

### Phase 03 — 自由折纸设计器(受限自由折)
- **内容**:`src/fold/freestyle.ts`(纯逻辑):在当前折叠态上由用户画折痕(两点定线 + 谷/山 + 层范围)生成折叠操作序列,复用 `splitFold`/`apply`;几何校验拒绝无效折痕;产出可被 `extract`/`simulate` 消费的自定义机型;localStorage 保存 + `#design=` URL 分享。
- **验收**:质量/面积守恒测试;序列化往返;折痕校验拒绝用例;自由折产物可提取气动参数并模拟飞行。

### Phase 04 — 3DOF 飞行物理(横滚/偏航/侧风,纯逻辑)
- **内容**:`src/aero/` 增加侧向状态(侧滑 β、偏航率、滚转/滚转率):龙骨前后面积分布 → 风标稳定项,上反角 → 横滚恢复项;风改为水平二维矢量 + 阵风序列(确定性种子);输出 3D 轨迹(x/y/z)。无侧风 + 对称构型退化为纵向 2D(等价性测试)。Canvas 2D 先以俯视 + 侧视双投影渲染。
- **版本**:FLIGHT_MODEL_VERSION 递增;全锚点回归(零侧风下锚点保持)。
- **验收**:退化等价、能量单调、确定性种子复现测试;侧风敏感性方向正确测试。

### Phase 05 — 三维渲染层(Three.js 可选视图)
- **内容**:引入 `three` 依赖(PLAN.md M4 既定选型);折纸完成态 3D 网格展示 + 3D 飞行轨迹/姿态回放;Canvas 2D 保持默认,3D 视图手动切换;`prefers-reduced-motion` 回退;渲染层零物理输入。
- **验收**:渲染仅消费 FoldState/Flight 的架构测试(import 边界);2D/3D 同一数据源;构建体积记录。

### Phase 06 — 经典机型图鉴扩展
- **内容**:补齐 AERO-AUDIT 明确缺失的 **Zero Fighter**(户田拓夫 2010 年 29.2 s 历史里程碑)折序(如无公开权威折图,标注工程近似);补充其他无剪裁可折经典;图鉴升级:机型详情页、纸规格 × 成绩对照、个人最佳一览。
- **验收**:新机型全量几何/气动测试 + 校准区间报告;折序数据文件化(planes/*.ts);卡片注明设计者与出处。

### Phase 07 — 竞技比赛扩展(精准着陆)
- **内容**:新增**精准着陆赛**(对靶线的落点偏差计分,物理可算、无需花式判定);赛制扩展(轮数/淘汰表);比赛历史记录页。
- **验收**:计分纯逻辑单测(含无效成绩边界);赛制状态机测试;与现有距离/滞空赛互不干扰。

### Phase 08 — 单人生涯模式
- **内容**:`src/game/career.ts`(纯逻辑):分段挑战链(机型 × 纸张 × 风况 × 目标的组合关卡)、进度状态、解锁规则、生涯纪录;localStorage 版本化存档 + 迁移策略;生涯主界面。
- **验收**:状态机测试、存档序列化与迁移测试、确定性种子关卡测试。

### Phase 09 — 成就系统与纪录墙
- **内容**:`src/game/achievements.ts`:成就定义为纯函数(状态 → 解锁);纪录墙聚合自由实验/挑战/正式赛/生涯最佳。
- **验收**:纯函数幂等测试;localStorage 键版本化。

### Phase 10 — i18n(zh/en)
- **内容**:文案集中化(`src/i18n/`),中文默认、英文完整覆盖;语言偏好持久化;分享链接保持语言无关。
- **验收**:键完整性测试(两语言键集合一致);UI 无硬编码漏网文案抽查。

### Phase 11 — 浏览器集成与端到端测试
- **内容**:浏览器环境烟囱链路:选纸 → 折叠(手动 + 自动)→ 飞行 → 结算 → 分享链接导入 → 存档恢复;移动端视口与触控目标检查。
- **验收**:CI 可复现的浏览器测试套件;失败可诊断(截图/日志)。

### Phase 12 — 性能基准与发布收尾
- **内容**:基准脚本(extract 耗时、单次模拟墙钟、渲染帧预算);构建体积与字体策略;README/文档与实现同步;全量回归 + 校准终检。
- **验收**:基准有数字记录且不劣化超阈值;文档与功能一致;全量测试绿。
